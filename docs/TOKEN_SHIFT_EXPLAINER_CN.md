## A 先看一句话

```callout info 核心规则
input_ids 是模型读到的 token。
labels 是该位置应该预测的下一个 token。
response_mask 判断这个目标是否属于回答。
```

P0、P1 表示题目的两个 token。
R0、R1 表示回答的两个 token。
EOS 是结束标记。
这些名字只是示意，不是具体文字。

## B 为什么输入与标签要错开一位？

完整序列是：`P0 P1 R0 R1 EOS`。

模型做的是“预测下一个 token”。
因此，我们给每个输入位置配一个后继目标。

| 位置 | 模型此时能看到的内容 | 应预测的目标 | 目标属于回答吗？ |
|---|---|---|---|
| 0 | P0 | P1 | 否 |
| 1 | P0、P1 | R0 | 是 |
| 2 | P0、P1、R0 | R1 | 是 |
| 3 | P0、P1、R0、R1 | EOS | 是 |

例如，位置1的任务是：读完题目，预测回答首 token。
它不是让模型用 P1 预测 P1。

因果注意力让各位置只能读取此前内容。
位置1看不到位置2的 R0。
虽然训练时把整个输入一起传入模型，仍不会偷看目标。

## C 三次切片是在构造四对预测任务

完整序列只有一条，并没有先准备两个不同句子。
输入和标签都从这同一条序列取出。

```text
完整序列：P0  P1  R0  R1  EOS
原始mask： 0   0   1   1    1
```

### 先想我们需要哪些配对

```text
当前位置的token → 下一个目标token
P0             → P1
P1             → R0
R0             → R1
R1             → EOS
```

每一行是一对相邻 token。
模型在该位置还能看到此前的上下文。
例如 P1 → R0 的完整条件是：读到 P0、P1，预测 R0。

### 输入取每对的左边

```text
P0  P1  R0  R1
```

最后一个 EOS 没有已知的下一个 token。
因此这里不让 EOS 再承担一个预测任务。
删除末尾就是取出四对中的左边。

### 标签取每对的右边

```text
P1  R0  R1  EOS
```

这组任务从 P0 开始预测它的后继 P1。
没有更早的输入位置来预测 P0。
因此标签删除开头，取出四对中的右边。
如果另加 BOS，也可以建立 BOS → P0 的任务。
当前例子没有加入 BOS。

```text
同一列是一对：
input_ids：P0  P1  R0  R1
labels：   P1  R0  R1  EOS
```

这不是让模型“复制输入”。
也不是重新生成一条标签序列。
labels是我们已知的后继token，用来评分模型的预测分布。

### mask为什么也删第一个位置？

原始mask描述完整序列中每个token的角色。
P0、P1属于题目，R0、R1、EOS属于回答。

```text
完整序列：P0  P1  R0  R1  EOS
原始mask： 0   0   1   1    1
```

标签删除了 P0，其余token保留原来的角色标记。
所以mask也删除 P0 对应的第一个0。

```text
labels：        P1  R0  R1  EOS
response_mask：  0   1   1    1
```

例如 R0 的标记原本是1，切片后仍是1。
mask必须跟着它所描述的标签走。

### 对应Python切片

```text
ids[:, :-1]  → 取所有样本，排除最后一列
ids[:, 1:]   → 取所有样本，排除第一列
mask[:, 1:]  → 与labels保留相同位置
```

冒号左侧表示batch维，此处保留所有样本。
冒号右侧表示token位置维，此处切掉一个边界。
三个结果都长4，所以能逐列计算loss并乘mask。

```callout info 用一句话记住
输入取相邻配对的左边，标签取右边。
mask是标签的角色说明，因此跟标签一起取右边。
```

## D 为什么 P1 下面的 mask 是 1？

```callout info 这一列的优化对象是 R0
位置1：input=P1，label=R0。
mask=1 表示“计入预测 R0 的 loss”。
它不表示“把 P1 当回答”。
```

mask 关注的是 labels 行。
位置0预测的是题目 token P1，因此不计入回答 loss。
位置1预测的是回答 token R0，因此要计入。

```text
错误的想法：input是prompt → 这一列一定不训练
正确的判断：label属于回答 → 这一列要计入loss
```

如果照 input 的角色写成 `[0,0,1,1]`，就会漏掉 R0。
模型也就失去了这一次对回答首 token 的优化信号。

## E mask 如何进入 PyTorch 的 loss？

模型先输出每个位置的词表分数。
再取出 labels 指定 token 的 log-prob。

```text
位置0 → log p(P1 | P0)
位置1 → log p(R0 | P0,P1)
位置2 → log p(R1 | P0,P1,R0)
位置3 → log p(EOS | P0,P1,R0,R1)
```

这是从分布中取目标的分数，不是要求生成结果总等于 label。
例如位置1给 R0 的概率越低，该目标的负 log-prob 越大。

用教学数值说明按元素乘 mask：

```text
token loss：   0.9  0.2  0.4  0.1
mask：           0    1    1    1
相乘后：         0  0.2  0.4  0.1
```

第一项不进入回答 loss。
另外三项再按算法要求求和或平均。
主RL还会用优势 A 为回答的 token 项加权。
mask 解决“哪些项参与”，优势解决“鼓励还是抑制”。

mask=0 不会从上下文中删除题目。
回答仍以题目为条件，梯度也可能经过题目位置的激活。
它只排除“预测题目 token”的直接 loss 项。

## F 最后区分两个问题

| 问题 | 由谁控制？ |
|---|---|
| 当前位置能看哪些 token？ | 因果 attention mask |
| 哪些预测要计入回答 loss？ | response_mask |

这张图解释主RL的回答评分。
本项目 packed SFT 则对完整文本计算 loss。
不能把主RL的 response mask 规则照搬到该 SFT 目标。

EOS只用于展示“回答含结束标记”时的对齐。
主RL token化接口不会自动添加 EOS。

自测：位置2的 input 是 R0，为什么 label 是 R1？
因为读到 R0 后，下一个要预测的 token 是 R1。
